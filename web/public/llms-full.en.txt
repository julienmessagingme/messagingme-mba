# Messaging Me API

REST API: contacts, WhatsApp and RCS messages, sends.

<a id="premier-appel"></a>

## First call

Create a record, or update it if it exists:

_Command_

```
curl -X POST https://api.messagingme.app/v1/contacts \
  -H "Authorization: Bearer mba_xxxxxxxxxxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{
  "phone": "+33612345678",
  "externalId": "crm-7781",
  "name": "Camille Roy",
  "fields": {
    "ville": "Lyon"
  },
  "tags": [
    "prospect"
  ],
  "consent": "opted_in",
  "consentSource": "formulaire-site"
}'
```

_200 response_

```
{
  "contactId": "5f0c1e2a-8b7d-4c3e-9a1f-2d6b7e8c9f01",
  "status": "created"
}
```

Details: [POST /v1/contacts](https://console.messagingme.app/developers/api/contacts.en.md#creer).

# Get started in ten minutes

From sign-up to the first message sent through the API, with your own phone to check each step. You need a WhatsApp number (yours, or one we provide) and a server that receives HTTPS requests.

<a id="espace"></a>

## 1. Create your workspace and connect your number

Sign up at `https://console.messagingme.app/signup`. The console chains the steps: connect a WhatsApp number (yours, through Meta’s window, or a provided number), then a page with the two commands that install the Claude Code plugin, your application’s key, and /messagingme:demarrer, which starts the setup.

With no number connected, nothing goes out: [`no_whatsapp_number`](https://console.messagingme.app/developers/api/errors.en.md#no_whatsapp_number).

<a id="cle"></a>

## 2. Create an API key

In the console, Developers > API keys. Tick at least sends:create (send) and conversations:read (read threads). The key (mba_…) is shown only once: keep it server-side, in an environment variable.

_Check the key_

```
curl https://api.messagingme.app/v1/templates \
  -H "Authorization: Bearer mba_xxxxxxxxxxxxxxxx"
```

A list, even empty, means the key works. Otherwise: [`unauthorized`](https://console.messagingme.app/developers/api/errors.en.md#unauthorized), [`missing_scope`](https://console.messagingme.app/developers/api/errors.en.md#missing_scope).

<a id="webhook"></a>

## 3. Receive events

Declare your server’s address in the console (Developers > Outgoing webhooks), or through the API with a key that carries webhooks:write. The secret (whsec_…) is shown only once: it is used to verify each signature.

_Command_

```
curl -X POST https://api.messagingme.app/v1/webhooks \
  -H "Authorization: Bearer mba_xxxxxxxxxxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{
  "url": "https://www.exemple.fr/messagingme/evenements",
  "description": "Mon application",
  "types": [
    "message.received",
    "template.status_changed"
  ]
}'
```

Verify the signature on the raw body, with the [SDK](https://console.messagingme.app/developers/api/sdk.en.md#webhook) or by hand ([the format](https://console.messagingme.app/developers/api/webhooks.en.md#signature)), then answer 2xx within 10 s.

<a id="premier-envoi"></a>

## 4. A first send

The fastest: from your phone, write to the workspace’s number. Your server receives message.received, with the record created for you. For 24 hours, the API can answer you with a free-form message:

_Command_

```
curl -X POST https://api.messagingme.app/v1/messages/whatsapp \
  -H "Authorization: Bearer mba_xxxxxxxxxxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{
  "phone": "+33612345678",
  "text": "Bien reçu, merci ! Nous revenons vers vous dans la journée."
}'
```

To write first, you need a template approved by Meta: create it in the console (Content > WhatsApp > Templates) or with [POST /v1/templates](https://console.messagingme.app/developers/api/templates.en.md#creer), wait for its approval (from a few minutes to 24 hours), then send it:

_Command_

```
curl -X POST https://api.messagingme.app/v1/sends \
  -H "Authorization: Bearer mba_xxxxxxxxxxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{
  "idempotencyKey": "premier-envoi-1",
  "target": {
    "template": {
      "name": "confirmation_commande",
      "language": "fr"
    }
  },
  "recipients": [
    {
      "phone": "+33612345678"
    }
  ],
  "params": [
    {
      "position": 1,
      "source": {
        "type": "attribute",
        "key": "name"
      },
      "fallback": "Bonjour"
    },
    {
      "position": 2,
      "source": {
        "type": "literal",
        "value": "8412"
      }
    }
  ]
}'
```

- Window closed: [`window_closed`](https://console.messagingme.app/developers/api/errors.en.md#window_closed); use a template.
- No card in Business Manager: [`131042`](https://console.messagingme.app/developers/api/errors.en.md#meta-131042).
- The number is not on WhatsApp: [`131026`](https://console.messagingme.app/developers/api/errors.en.md#meta-131026).

# TypeScript SDK

The TypeScript client of the API: calls typed by path and method, typed errors, and signature verification for outgoing webhooks. Its types are generated from the [OpenAPI contract](https://console.messagingme.app/developers/api.en.md#openapi): a path, body or response that does not exist does not compile.

<a id="installation"></a>

## Installation

_Installation_

```
npm install github:julienmessagingme/messagingme-sdk#v0.3.1
```

- No dependency. Node 20 or later, Deno, Bun, and runtimes that expose fetch and Web Crypto.
- ESM only: import it with import, not require.
- Installing from GitHub needs git on the machine (a minimal Docker image does not always have it).
- A published version never changes: the version follows the tag after the #.

<a id="premier-appel"></a>

## A first call

The API key (`mba_…`) is created in the console, Developers > API keys. Keep it server-side. The client calls the production API; `baseUrl` points to another one.

_TypeScript_

```
import { createClient } from '@messagingme/sdk';

const api = createClient({ apiKey: process.env.MESSAGINGME_API_KEY! });

// Créer une fiche, ou la mettre à jour si elle existe.
const { contactId, status } = await api.POST('/v1/contacts', {
  body: { phone: '+33612345678', name: 'Camille Roy', consent: 'opted_in', consentSource: 'formulaire-site' },
});

// Lire une fiche : les paramètres de chemin passent par path.
const fiche = await api.GET('/v1/contacts/{contactId}', { path: { contactId } });

// Les conversations qui attendent une réponse, par pages : query.
const page = await api.GET('/v1/conversations', { query: { needsReply: true, limit: 20 } });

// Un envoi, rejouable sans doublon avec la même clé d’idempotence. Ici un modèle sans variable :
// avec variables, ajoutez params (voir Envois).
const envoi = await api.POST('/v1/sends', {
  body: {
    target: { template: { name: 'bienvenue', language: 'fr' } },
    recipients: [{ phone: '+33612345678' }],
  },
  idempotencyKey: 'commande-7781',
});
```

The scope of each route: [Authentication, limits and errors](https://console.messagingme.app/developers/api/reference.en.md#authentification).

<a id="erreurs"></a>

## Errors

Any non-2xx response throws `ApiError`, with the status, the API code and, when the API says so, the delay to wait. The SDK retries nothing on its own.

_TypeScript_

```
import { ApiError } from '@messagingme/sdk';

try {
  await api.POST('/v1/messages/whatsapp', { body: { contactId, text: 'Bonjour' } });
} catch (e) {
  if (e instanceof ApiError) {
    if (e.code === 'window_closed') { /* la personne n’a pas écrit depuis 24 h : passer par un modèle */ }
    if (e.code === 'meta_rejected') { /* Meta a refusé : e.metaCode dit pourquoi (131047, 132000…) */ }
    if (e.status === 429 && e.retryAfter !== null) { /* attendre e.retryAfter secondes */ }
  }
  throw e;
}
```

- `code` is set on every API error response; it is null when a generic error page replaced the response on the way (a 5xx).
- `metaCode` carries Meta’s error number on meta_rejected (since version 0.2.0): [Meta errors](https://console.messagingme.app/developers/api/errors.en.md#meta).
- `upgradeUrl` is set on a 402 (plan_feature_unavailable, plan_limit_reached): the page where the plan is changed.

<a id="webhook"></a>

## Verifying a webhook

Pass the RAW body, as received: the signature covers its bytes. The format is described in [Outgoing webhooks](https://console.messagingme.app/developers/api/webhooks.en.md#signature).

_TypeScript_

```
import { verifyWebhook, WebhookVerificationError } from '@messagingme/sdk';

// Une route qui reçoit les webhooks sortants (ici avec l’API Request standard).
export async function POST(req: Request) {
  const body = await req.text();
  try {
    const event = await verifyWebhook({ secret: process.env.MESSAGINGME_WEBHOOK_SECRET!, headers: req.headers, body });
    if (event.type === 'message.received') console.log(event.data.text);
    return new Response(null, { status: 204 });
  } catch (e) {
    if (e instanceof WebhookVerificationError) return new Response(null, { status: 401 });
    throw e;
  }
}
```

- During a secret rotation, the old one keeps signing for 24 h: pass both, secret: [new, old].
- A timestamp more than 5 minutes away is refused (toleranceSeconds to change it).
- The same event can arrive twice (retry, replay): deduplicate by event.id, equal to the webhook-id header.

> **Required**
>
> An empty or unreadable secret throws a TypeError: it is a configuration error, not a wrong signature. Do not turn it into a 401.

## POST /v1/contacts

Creates or updates a record.

Scope: `contacts:write`

### Request

| Field | Required | Description |
| --- | --- | --- |
| `contactId` : uuid | At least one key | The record id, returned when it is created. [Identifying a person](https://console.messagingme.app/developers/api/concepts.en.md#identification) |
| `externalId` : string | At least one key | Your id for the person, unique per workspace, 512 characters at most. |
| `phone` : string | At least one key | The phone number, in international format (+33…). |
| `bsuid` : string | At least one key | The WhatsApp id of a person with no visible number. |
| `name` : string | No | The display name. |
| `fields` : object | No | The record fields, by technical key or fld_ code, 20 at most. Text, number or boolean value, stored as text. A field unknown to the workspace is refused: create it first in the console (Library > Fields). |
| `tags` : string[] | No | Tags to add, 20 at most. None is removed: PATCH does that. A tag unknown to the workspace is refused: declare it first in the console (Library > Tags). |
| `consent` : string | No | Missing: unchanged. Values: `opted_in` , `opted_out`. [Consent and STOP](https://console.messagingme.app/developers/api/concepts.en.md#consentement) |
| `consentSource` : string | No | Where the consent comes from, 100 characters at most. Missing: api. |

An unknown key is ignored. Refused: `optIn` , `optInSource` (the former names of consent and consentSource).

_Command_

```
curl -X POST https://api.messagingme.app/v1/contacts \
  -H "Authorization: Bearer mba_xxxxxxxxxxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{
  "phone": "+33612345678",
  "externalId": "crm-7781",
  "name": "Camille Roy",
  "fields": {
    "ville": "Lyon"
  },
  "tags": [
    "prospect"
  ],
  "consent": "opted_in",
  "consentSource": "formulaire-site"
}'
```

### Errors

| Status | Code | Cause |
| --- | --- | --- |
| 400 | `invalid_body` | Malformed or refused field, too many fields or tags, field or tag unknown to the workspace; the message names it. |
| 404 | `unknown_contact` | No record found, and neither phone nor bsuid to create one (an externalId alone, for instance). |
| 409 | `opted_out` | consent opted_in on an opted-out record. Nothing is changed. |
| 400, 409 | `invalid_recipient` `invalid_phone` `identity_conflict` | Record keys missing, unreadable or contradictory: [Identifying a person](https://console.messagingme.app/developers/api/concepts.en.md#identification) |

| Field | Meaning |
| --- | --- |
| `results` | One result per item, in order: index, status (created, updated or error), and for a refusal code and reason. |

| Status | Code | Cause |
| --- | --- | --- |

### Notes

- A refused item (malformed, too many fields or tags, unknown field or tag) does not stop the others.
- Items that designate the same person are written in the order of the list.
- Importing a file: send it in batches of 50, as below (a module: .mjs file). The rate depends on your workspace’s plan (the x-ratelimit headers of every response tell it), and written records have a quota of 20000 a day. A 429 wrote nothing: wait for Retry-After (until midnight for the daily quota) and send the same records again. A very large file goes faster through the console’s CSV import.

_Importing a simple CSV (phone,name), Node.js_

```
import { readFileSync } from 'node:fs';

const lignes = readFileSync('contacts.csv', 'utf8').trim().split(/\r?\n/).slice(1);
const fiches = lignes.map((l) => { const [phone, name] = l.split(','); return { phone, name }; });

for (let i = 0; i < fiches.length; ) {
  const r = await fetch('https://api.messagingme.app/v1/contacts/batch', {
    method: 'POST',
    headers: { authorization: 'Bearer mba_xxxxxxxxxxxxxxxx', 'content-type': 'application/json' },
    body: JSON.stringify({ contacts: fiches.slice(i, i + 50) }),
  });
  if (r.status === 429) {
    await new Promise((ok) => setTimeout(ok, Number(r.headers.get('retry-after') ?? 2) * 1000));
    continue;
  }
  if (!r.ok) throw new Error(await r.text());
  const { results } = await r.json();
  for (const e of results.filter((x) => x.status === 'error')) console.log(i + e.index, e.code, e.reason);
  i += 50;
}
```

## POST /v1/sends

Starts an asynchronous, idempotent send to 1 to 50 recipients.

Scope: `sends:create`

> **Required**
>
> An idempotency key: Idempotency-Key header or idempotencyKey field. [Idempotency](https://console.messagingme.app/developers/api/concepts.en.md#idempotence)

### Request

| Field | Required | Description |
| --- | --- | --- |
| `idempotencyKey` : string | Yes, here or in the Idempotency-Key header | The key that makes the call safe to replay without a double send, 255 characters at most. [Idempotency](https://console.messagingme.app/developers/api/concepts.en.md#idempotence) |
| `target` : object | Yes | What goes out: a template, a scenario, a block or an RCS message. |

<a id="cibles"></a>

#### Target types

target carries exactly one key:

| Key | Value | Channel |
| --- | --- | --- |
| `template` | an object: name and language of an approved template (GET /v1/templates) | WhatsApp |
| `scenario` | the scn_ code or the name of a scenario (GET /v1/scenarios) | that of its first send |
| `node` | the nod_ code of a block (Content > Blocks, or entryNode in GET /v1/scenarios) | that of its first send |
| `rcsMessage` | the name of a message in Content > RCS messages (GET /v1/rcs-messages) | RCS, from the workspace’s RCS agent |

<a id="destinataires"></a>

#### Recipients

Each item of recipients:

| Field | Required | Description |
| --- | --- | --- |
| `contactId` : uuid | At least one key | The record id, returned when it is created. [Identifying a person](https://console.messagingme.app/developers/api/concepts.en.md#identification) |
| `externalId` : string | At least one key | Your id for the person, unique per workspace, 512 characters at most. |
| `phone` : string | At least one key | The phone number, in international format (+33…). |
| `bsuid` : string | At least one key | The WhatsApp id of a person with no visible number. |
| `consent` : string | No | Written on the record before filtering. opted_out opts the record out and skips this recipient. Values: `opted_in` , `opted_out`. [Consent and STOP](https://console.messagingme.app/developers/api/concepts.en.md#consentement) |
| `consentSource` : string | No | Where the consent comes from, 100 characters at most. Missing: api. |
| `variables` : object | No | Values specific to this recipient, never written on the record. 50 at most, of 1024 characters at most; names in letters, digits, _, . or -. |

An unknown key is ignored.

- Unknown recipient with a phone: record created, except with a whatsapp_session opening. Otherwise skipped (`unknown_contact`).
- Malformed recipient: skipped (`invalid_recipient`, `invalid_phone`), the send goes on.

<a id="parametres"></a>

#### Parameters and variables

Each item of params:

| Field | Required | Description |
| --- | --- | --- |
| `position` : integer | Yes | The template variable: 1 for {{1}}. Positions 1 to N, with no gap. |
| `source` : object | Yes | Where the value comes from. |
| `fallback` : string | No | The fallback value, when the source is empty. |

An unknown key is ignored.

| source.type | With | Reads |
| --- | --- | --- |
| `field` | `key` | a record field, by its key |
| `attribute` | `key` : `name` , `phone` , `bsuid` , `wa_id` | a record attribute |
| `now` |  | today’s date (DD/MM/YYYY, Paris time) |
| `literal` | `value` | a fixed text |
| `variable` | `key` | a recipient variable (recipients[].variables), on a template only |

Depending on the target:

| Target | params | recipients[].variables |
| --- | --- | --- |
| template | One entry per body variable (GET /v1/templates). Other count: 422 `unsendable_target`. | Read by the variable source. Missing and without fallback: recipient skipped (`missing_variable`). |
| scenario opening with a template | Parameterize that template (openingTemplate), any source except variable. | Refused (400 `invalid_body`). |
| block, scenario opening with RCS | Refused (400 `invalid_body`). A block fills its template with the fields associated with its variables in the console. | Refused (400 `invalid_body`). |
| RCS message | Refused (400 `invalid_body`). | `{{commande}}` : variables.commande, otherwise the record field commande, otherwise empty. |

<a id="ouverture"></a>

#### Opening message

The first message the target sends decides the rules, not the type of the targeted block. The response returns it in opening.

| First send | opening | Rule |
| --- | --- | --- |
| a template | `whatsapp_template` | Goes to someone who has not written. |
| an RCS block | `rcs` | Goes to someone who has not written. Record without a number: skipped (`no_phone`). |
| a quick message, a question, a form, an agent | `whatsapp_session` | 24-hour window required per recipient, otherwise skipped (`window_closed`). |
| a wait before any send, nothing, several possible templates, an unnamed template | (none) | 422 `unsendable_target`, reason in the message. |

- A single branch able to send a session message: the window is required for everyone.
- Scenario with whatsapp_session: refused. Target its entry block (node target, code in entryNode).
- A block accepts all three openings.
- A send plays the published version: a never-published scenario is refused.

| Target | category |
| --- | --- |
| template | Refused: read at Meta, marketing or utility. Unreadable or other: 422 `template_category_unknown`. |

| Category | Recipients skipped |
| --- | --- |
| `marketing` | Every recipient who is not opted_in (`no_consent`). |

## POST /v1/templates

Creates a template in Meta’s format and submits it for review.

Scope: `templates:write`

Meta’s body (Cloud API, message templates): name, language, category, components. It goes through the Templates screen’s creation: its links are tracked and its checks apply.

| Field | Meaning |
| --- | --- |

### Errors

In the order they are checked:

| Status | Code | Cause |
| --- | --- | --- |
| 400 | `invalid_body` | Body outside the format, naming the field; then an unknown {key} field in a button URL. |
| 409 | `no_whatsapp_number` | Workspace without a WhatsApp account. |
| 429 | `rate_limited` | All header upload slots are taken, or Meta is briefly unavailable: retry after Retry-After. |
| 422 | `invalid_header_media` | Header file not found, too large, or of another type. |
| 422 | `template_rejected` | A link could not be tracked. |
| 409 | `meta_auth_failed` | Meta refuses the workspace token: reconnect the WhatsApp account. |
| 422 | `meta_rejected` | Meta refuses the template (name already taken in this language, content): its reason follows. |

### Notes

- Meta’s bounds: body 1,024 characters, header and footer 60, button text 25, 10 buttons.
- Header file: JPEG or PNG image up to 5 MB, MP4 video or PDF document up to 16 MB. The address must not redirect.
- Not on this route: carousel, authentication, Flow, named variables.

> **Caution**
>
> No idempotency: replaying the call with the same name is refused by Meta.

# Concepts

The rules shared by several routes.

<a id="identification"></a>

## Identifying a person

A person is a record. Four keys designate it:

| Key | What it is |
| --- | --- |
| `contactId` | Record id, created with it. Shown on the mini-CRM record (“API identifier”, Copy button). |
| `externalId` | The person’s id in your tool (CRM, marketing platform), kept on the record. Unique per workspace, 512 characters at most. |
| `phone` | Phone number in international format (+33…). Without a country code: read as French. |
| `bsuid` | WhatsApp id of a person writing under a username, with no visible number. |

- At least one key, otherwise `invalid_recipient`. Unreadable number: `invalid_phone`.
- All the keys given designate the same record, otherwise `identity_conflict` and nothing is changed.
- A key the record does not carry yet is attached to it: an externalId sent with the phone number is set on the record.
- contactId is never attached: it exists, or it is unknown.

| Route | No record matches |
| --- | --- |
| POST /v1/contacts, POST /v1/contacts/batch | Record created with a phone or a bsuid. |
| POST /v1/sends | Record created with a phone, except with a whatsapp_session opening. |
| Other routes | Nothing created. |

No creation possible: `unknown_contact`.

> **Note**
>
> The sending address comes from the record, never from the key received. WhatsApp: the phone number, otherwise the BSUID. RCS: the phone number (record without one: `no_phone`).

<a id="consentement"></a>

## Consent and STOP

| Field | Effect |
| --- | --- |
| `consent` = `opted_in` | Records the consent. |
| `consent` = `opted_out` | Opts out: status, date, audit log entry. |
| `consent` missing | No change. |
| `consentSource` | Origin of the consent. Missing: api. |

> **Caution**
>
> opted_in never lifts a STOP: on an opted-out record, 409 `opted_out`, nothing is changed. Only an operator or the person themselves can re-subscribe them.

- POST /v1/sends: consent per recipient, same effect, written on the record before filtering. opted_out skips the recipient.
- Requirements of a send category: [Category](https://console.messagingme.app/developers/api/sends.en.md#categorie); of an RCS message: [POST /v1/messages/rcs](https://console.messagingme.app/developers/api/messages.en.md#message-rcs).

<a id="fenetre-24h"></a>

## The 24-hour window

- Meta rule: opens when the person writes, closes 24 hours after their last message.
- Outside the window, only a template can go out (POST /v1/sends).
- Applies to [POST /v1/messages/whatsapp](https://console.messagingme.app/developers/api/messages.en.md#message-whatsapp) and to sends opening with whatsapp_session ([Opening message](https://console.messagingme.app/developers/api/sends.en.md#ouverture)). Closed: `window_closed`.
- No window over RCS.

<a id="idempotence"></a>

## Idempotency

Only POST /v1/sends carries an idempotency key. Messages have none ([Message or send](https://console.messagingme.app/developers/api/messages.en.md#messages-simples)).

> **Required**
>
> Key required: Idempotency-Key header or idempotencyKey field. Missing: 400 `idempotency_key_required`.

_Header_

```
Idempotency-Key: confirmation-8412
```

| Case | Response |
| --- | --- |
| Same key, same body | The first call’s 201 report, as is, even if the target has changed since. Nothing is sent again. |
| Same key, different body | 422 `idempotency_key_reused` |
| First call still running | 409 `idempotency_in_progress` |
| First call cut off before its response (dropped connection, outage) | Replaying the same key returns its report if the send went through; otherwise the key stays in progress for at most 5 min, then is released, and the same key creates the send, once. |
| Header and field present and different | 400 `invalid_body` |
| Send refused (target not found, number missing…) | Key released: the fixed call goes out with the same one. |

Key lifetime: at least 24 h. Building the key for a tool that calls per contact: [The idempotency key](https://console.messagingme.app/developers/api/guides/per-contact.en.md#cle).

# Meta pitfalls

Messaging Me goes through Meta’s official WhatsApp platform. Its rules apply to every message, whatever tool sends it: here they are, with the code you will get when one of them blocks.

<a id="fenetre"></a>

## The 24-hour window

A free-form message (text, image, buttons) only goes out within 24 hours of the person’s last message. After that, only a template approved by Meta can go out. When it knows, the API refuses before Meta: [`window_closed`](https://console.messagingme.app/developers/api/errors.en.md#window_closed); otherwise Meta answers [`131047`](https://console.messagingme.app/developers/api/errors.en.md#meta-131047).

A conversation says whether its window is open: [GET /v1/conversations/{conversationId}](https://console.messagingme.app/developers/api/conversations.en.md#lire). [The rule in detail](https://console.messagingme.app/developers/api/concepts.en.md#fenetre-24h).

<a id="modeles"></a>

## Templates and their review

- Meta reviews each template, in a few minutes or up to 24 hours. Only an approved template goes out.
- Three categories: marketing, utility (transactional) and authentication. Meta can change the category you chose, and the price changes with it.
- A template can be paused for low quality ([`132015`](https://console.messagingme.app/developers/api/errors.en.md#meta-132015)), then permanently disabled if it happens again ([`132016`](https://console.messagingme.app/developers/api/errors.en.md#meta-132016)).
- A send’s parameters must match the template, in number ([`132000`](https://console.messagingme.app/developers/api/errors.en.md#meta-132000)) and format ([`132012`](https://console.messagingme.app/developers/api/errors.en.md#meta-132012)).
- Follow the status: [GET /v1/templates/{name}](https://console.messagingme.app/developers/api/templates.en.md#statut), or the event `template.status_changed`.

<a id="facturation"></a>

## What Meta charges for

Meta charges template messages by category and by the recipient’s country. Service messages (replies within the 24-hour window) have their own terms, which changed on October 1, 2026. Messaging Me does not set these prices: Meta’s official rate card is the reference.

[Meta’s pricing](https://developers.facebook.com/docs/whatsapp/pricing)

<a id="paiement"></a>

## The card in Business Manager

Meta requires a valid payment method on the WhatsApp account for what it charges, starting with templates, whatever the Messaging Me plan. Without it: [`131042`](https://console.messagingme.app/developers/api/errors.en.md#meta-131042).

<a id="consentement"></a>

## Consent and STOP

Meta requires consent before writing first to someone. Messaging Me keeps it on the record and refuses a marketing send without it ([`no_consent`](https://console.messagingme.app/developers/api/errors.en.md#no_consent)). A person who replies STOP is opted out ([`opted_out`](https://console.messagingme.app/developers/api/errors.en.md#opted_out)): the API never resubscribes them.

The person can also refuse your business’s marketing within WhatsApp itself: [`131050`](https://console.messagingme.app/developers/api/errors.en.md#meta-131050). [The rule in detail](https://console.messagingme.app/developers/api/concepts.en.md#consentement).

<a id="qualite"></a>

## Number quality

Meta rates each number’s quality from the blocks and reports it receives, and decides how many different people it can reach per 24 hours. Low quality restricts sending ([`131048`](https://console.messagingme.app/developers/api/errors.en.md#meta-131048)): a Messaging Me campaign then pauses, and nothing restarts it on its own. Write to people who agreed to it, with content they expect.

<a id="debit"></a>

## Throughput

- A number has a maximum sending throughput: [`130429`](https://console.messagingme.app/developers/api/errors.en.md#meta-130429).
- Too many messages to the same person in a short time: [`131056`](https://console.messagingme.app/developers/api/errors.en.md#meta-131056). The other recipients are not affected.
- The API also has its own limits, per minute and per day: [`rate_limited`](https://console.messagingme.app/developers/api/errors.en.md#rate_limited), [`quota_exceeded`](https://console.messagingme.app/developers/api/errors.en.md#quota_exceeded) (wait for `retry-after`). [The limits](https://console.messagingme.app/developers/api/reference.en.md#debit).

<a id="marketing"></a>

## The per-person marketing limit

Meta limits how many marketing messages a person receives, across all businesses. Beyond it, your message is not delivered ([`131049`](https://console.messagingme.app/developers/api/errors.en.md#meta-131049)), without you having done anything wrong. Do not retry right away: wait at least 24 hours.

<a id="nom-affiche"></a>

## The display name

The name the person sees for the number goes through Meta’s review. Check its status in WhatsApp Manager before sending, and fix it there if it is rejected.

<a id="injoignable"></a>

## The unreachable number

A number that is not on WhatsApp, a person who has not accepted WhatsApp’s terms or whose app is too old: [`131026`](https://console.messagingme.app/developers/api/errors.en.md#meta-131026). Use another channel (RCS, email).

<a id="medias"></a>

## Files

- Meta keeps a received file for 7 days only: download it as soon as the event `message.received` arrives ([GET /v1/messages/{messageId}/media](https://console.messagingme.app/developers/api/conversations.en.md#media)). After that: [`media_expired`](https://console.messagingme.app/developers/api/errors.en.md#media_expired).
- A file sent must have a type and size WhatsApp accepts: [`131053`](https://console.messagingme.app/developers/api/errors.en.md#meta-131053).

>
> All the codes, and what Messaging Me already does on its own: [Meta errors](https://console.messagingme.app/developers/api/errors.en.md#meta).

## Sending a template

The template must be approved by Meta ([GET /v1/templates/{name}](https://console.messagingme.app/developers/api/templates.en.md#statut)). The idempotency key taken from the order number prevents a duplicate for 24 hours, even if the route is called again.

_app/api/confirmation/route.ts_

```
import { ApiError } from '@messagingme/sdk';
import { messagingme } from '../../../lib/messagingme';

// POST /api/confirmation, avec phone (au format +33…) et commande dans le corps JSON.
export async function POST(req: Request) {
  const { phone, commande } = (await req.json()) as { phone?: unknown; commande?: unknown };
  if (typeof phone !== 'string' || typeof commande !== 'string') {
    return Response.json({ error: 'phone et commande requis' }, { status: 400 });
  }
  try {
    const envoi = await messagingme.POST('/v1/sends', {
      body: {
        // Le modèle a deux variables : le nom du contact, puis le numéro de commande.
        target: { template: { name: 'confirmation_commande', language: 'fr' } },
        recipients: [{ phone, variables: { commande } }],
        params: [
          { position: 1, source: { type: 'attribute', key: 'name' }, fallback: 'Bonjour' },
          { position: 2, source: { type: 'variable', key: 'commande' } },
        ],
      },
      // Rappelée avec la même commande pendant 24 h, la route ne renvoie pas le message.
      idempotencyKey: `commande-${commande}`,
    });
    return Response.json({ sendId: envoi.sendId, skipped: envoi.skipped });
  } catch (e) {
    if (e instanceof ApiError) {
      // e.code est stable (voir le catalogue des erreurs) ; e.metaCode porte le numéro de Meta sur meta_rejected.
      return Response.json({ code: e.code, metaCode: e.metaCode, error: e.message }, { status: e.status });
    }
    throw e;
  }
}
```

- An opted-out recipient or one without consent is not an error: they come back in `skipped`, with the reason.
- An error carries `code` (the catalog: [API codes](https://console.messagingme.app/developers/api/errors.en.md#codes)) and, on [`meta_rejected`](https://console.messagingme.app/developers/api/errors.en.md#meta_rejected), Meta’s number: `e.metaCode`.

## Receiving webhooks

Declare the endpoint `https://votre-domaine/api/webhooks/messagingme` in the console (Developers > Outgoing webhooks) or with [POST /v1/webhooks](https://console.messagingme.app/developers/api/webhook-endpoints.en.md#creer), and tick message.failed: it is unticked by default.

_app/api/webhooks/messagingme/route.ts_

```
import { verifyWebhook, WebhookVerificationError } from '@messagingme/sdk';

export async function POST(req: Request) {
  // Le corps BRUT : la signature porte sur ses octets.
  const body = await req.text();
  let event;
  try {
    event = await verifyWebhook({ secret: process.env.MESSAGINGME_WEBHOOK_SECRET!, headers: req.headers, body });
  } catch (e) {
    if (e instanceof WebhookVerificationError) return new Response(null, { status: 401 });
    throw e;
  }
  // Un même événement peut arriver deux fois : dédoublonnez par event.id.
  if (event.type === 'message.received') console.log('reçu', event.data.contact, event.data.text);
  if (event.type === 'message.failed') console.warn('échec', event.data.meta_code, event.data.reason);
  // Répondre vite (moins de 10 s) : un traitement long se fait après, sinon le webhook est réessayé.
  return new Response(null, { status: 204 });
}
```

> **Required**
>
> Read the RAW body (req.text()), never req.json() before verification: the signature covers the bytes received. Answer within 10 s, otherwise the delivery is retried.

```
export interface Appointment {

  phone: string; // E.164: +33612345678
  firstName: string;
  time: string; // as the patient reads it: '10:30 AM'
```

The day-before job, run every evening by your host’s scheduler. It sends through [POST /v1/sends](https://console.messagingme.app/developers/api/sends.en.md#envoi), with an idempotency key taken from the appointment and its time: run again the same evening, it does not send twice. A recipient set aside (STOP, plan limit) is not an error, it comes back in skipped with its reason; an error on one appointment does not stop the others, an exceeded rate (rate_limited) waits the delay the API gives, and the daily quota reached (quota_exceeded) stops the job until the next day.

_jobs/reminders.ts_

```
import { ApiError } from '@messagingme/sdk';
import { messagingme } from '../lib/messagingme';
import { saveReminder, tomorrowsAppointments, type Appointment } from '../lib/calendar';

// The template appointment_reminder (language en) has two variables, the first name then the time, and two quick
// reply buttons: Confirm and Reschedule.
function sendReminder(appointment: Appointment) {
  return messagingme.POST('/v1/sends', {
    body: {
      target: { template: { name: 'appointment_reminder', language: 'en' } },
      recipients: [{ phone: appointment.phone, variables: { firstName: appointment.firstName, time: appointment.time } }],
      params: [
        { position: 1, source: { type: 'variable', key: 'firstName' } },
        { position: 2, source: { type: 'variable', key: 'time' } },
      ],
    },
    // Run twice the same evening, the job does not send twice; a moved appointment gets a new key.
    idempotencyKey: `reminder-${appointment.id}-${encodeURIComponent(appointment.time)}`,
  });
}

// Run once a day, the evening before (a cron of your host). One failed reminder never stops the others.
export async function dayBeforeReminders(): Promise<void> {
  for (const appointment of await tomorrowsAppointments()) {
    try {
      let send;
      try {
        send = await sendReminder(appointment);
      } catch (e) {
        // Too many calls in the minute: wait what the API says (60 s at most), then try once more.
        if (!(e instanceof ApiError) || e.code !== 'rate_limited') throw e;
        await new Promise((r) => setTimeout(r, Math.min(e.retryAfter ?? 60, 60) * 1000));
        send = await sendReminder(appointment);
      }
      // A refused recipient (STOP, no number, plan limit) is not an error: it is listed in skipped.
      if (send.skippedTotal > 0) console.warn(`reminder ${appointment.id} not sent: ${send.skipped[0]?.reason}`);
      else await saveReminder(appointment, send.sendId);
    } catch (e) {
      // The quota of the day is reached: nothing more goes out before tomorrow, stop here.
      if (e instanceof ApiError && e.code === 'quota_exceeded') { console.error('daily quota reached', e); return; }
      console.error(`reminder ${appointment.id} failed`, e);
    }
  }
}
```

## The route that receives the replies

Declare its address with `create_webhook_endpoint` or with [POST /v1/webhooks](https://console.messagingme.app/developers/api/webhook-endpoints.en.md#creer), with the types message.received, ticked by default, and agent.action, unticked by default: tick it.

_app/api/webhooks/messagingme/route.ts_

```
import { verifyWebhook, WebhookVerificationError } from '@messagingme/sdk';
import { messagingme } from '../../../../lib/messagingme';
import { freeSlots, lastReminder, markConfirmed, move } from '../../../../lib/calendar';

// Subscribed to message.received (the Confirm button, ticked by default) and agent.action (the AI agent’s two
// actions, Reschedule request and Slot choice), unchecked by default on a webhook address: tick it.
export async function POST(req: Request) {
  // The RAW body: the signature covers its bytes.
  const body = await req.text();
  let event;
  try {
    event = await verifyWebhook({ secret: process.env.MESSAGINGME_WEBHOOK_SECRET!, headers: req.headers, body });
  } catch (e) {
    if (e instanceof WebhookVerificationError) return new Response(null, { status: 401 });
    throw e;
  }
  if (event.type !== 'message.received' && event.type !== 'agent.action') return new Response(null, { status: 204 });
  const contact = event.data.contact;
  // A button reply carries its label only, not the message it answers: tie it to the last reminder of the number.
  const appointment = contact?.phone ? await lastReminder(contact.phone) : null;
  if (!contact || !appointment) return new Response(null, { status: 204 });
  if (event.type === 'message.received' && event.data.button === 'Confirm') await markConfirmed(appointment);
  if (event.type === 'agent.action') {
    const { action, fields } = event.data;
    let text: string | null = null;
    if (action.name === 'Reschedule request') text = await freeSlots(appointment, 3);
    if (action.name === 'Slot choice' && fields.slot !== undefined) text = await move(appointment, String(fields.slot));
    if (text) await messagingme.POST('/v1/messages/whatsapp', { body: { contactId: contact.id, text } });
  }
  // The webhook waits 10 s for this answer, then retries the same event (same event.id): keep the work above
  // short, and your calendar functions safe to run twice.
  return new Response(null, { status: 204 });
}
```

```
import { book, offerSlots } from '../../../../lib/calendar';

// Subscribed to agent.action: the AI agent’s two actions, Appointment request (fields reason and city) and Slot
// choice (field slot). The type is unchecked by default on a webhook address. An action fires once a day per
// customer, with the fields known at that moment: its instruction tells the agent to wait for the city.
export async function POST(req: Request) {
  // The RAW body: the signature covers its bytes.
  const body = await req.text();
  let event;
  try {
    event = await verifyWebhook({ secret: process.env.MESSAGINGME_WEBHOOK_SECRET!, headers: req.headers, body });
  } catch (e) {
    if (e instanceof WebhookVerificationError) return new Response(null, { status: 401 });
    throw e;
  }
  if (event.type !== 'agent.action' || !event.data.contact) return new Response(null, { status: 204 });
  const { action, fields, contact } = event.data;
  let text: string | null = null;
  if (action.name === 'Appointment request') text = await offerSlots(String(fields.city ?? ''), 3);
  if (action.name === 'Slot choice' && fields.slot !== undefined) text = await book(event.id, String(fields.slot));
  if (text) await messagingme.POST('/v1/messages/whatsapp', { body: { contactId: contact.id, text } });
  // The webhook waits 10 s for this answer, then retries the same event (same event.id): keep the work above
  // short, and your calendar functions safe to run twice.
  return new Response(null, { status: 204 });
}
```

## The Stripe webhook

In the Stripe webhook your app already has, on invoice.payment_failed. The send goes through [POST /v1/sends](https://console.messagingme.app/developers/api/sends.en.md#envoi), with an idempotency key taken from the invoice: the same event delivered twice within 24 hours sends one message. A failed WhatsApp send does not change the answer to Stripe, which would otherwise retry the webhook, then disable it. No Messaging Me webhook address is needed.

_app/api/stripe/route.ts_

```
import { messagingme } from '../../../lib/messagingme';
import { userOfCustomer, verifiedStripeEvent } from '../../../lib/billing';

// Your Stripe webhook, the one you already have. The template payment_failed is UTILITY (an account alert): one
// variable, the first name, and a URL button to your billing page.
export async function POST(req: Request) {
  const event = await verifiedStripeEvent(req);
  if (!event) return new Response(null, { status: 400 });
  if (event.type === 'invoice.payment_failed') {
    const invoice = event.data.object;
    const user = await userOfCustomer(invoice.customer);
    if (user) {
      // A failed WhatsApp send never fails the Stripe webhook: Stripe would retry it, then disable it.
      try {
        const send = await messagingme.POST('/v1/sends', {
          body: {
            target: { template: { name: 'payment_failed', language: 'en' } },
            recipients: [{ phone: user.phone, variables: { firstName: user.firstName } }],
            params: [{ position: 1, source: { type: 'variable', key: 'firstName' } }],
          },
          // Stripe may deliver the same event again: within 24 hours, one message per invoice.
          idempotencyKey: `payment-${invoice.id}`,
        });
        // A refused recipient (STOP, plan limit) is not an error: it is listed in skipped, with its reason.
        if (send.skippedTotal > 0) console.warn(`payment ${invoice.id} not sent: ${send.skipped[0]?.reason}`);
      } catch (e) {
        console.error(`payment ${invoice.id}: WhatsApp send failed`, e);
      }
    }
  }
  return new Response(null, { status: 200 });
}
```

# Events

<a id="signaux"></a>

## What the console sends back

When something happens on a contact, the console pushes an event, with the contact’s current state, to the tool your administrator connected in Settings > Integrations.

- Only the tools offered in Settings > Integrations receive them: this is not a webhook to an address of your choice.
- Names start with `em_`, and do not change from one tool to another, nor do the field names. A text is at most 300 characters long; a missing or empty value is not sent.
- The profile is designated by your own id, `externalId`: a contact without one is not sent back (the settings screen counts those signals). Pass it on every call: contact, send, message.
- The same event can arrive twice: deduplicate on `em_event_id`, which is stable.

> **Caution**
>
> A message’s text is never sent back. A conversation summary is sent only when the option is on in the settings: it contains the customer’s words.

## Timing

- Less than a minute in normal conditions. Every event carries the time it happened, not the time it arrives.
- Behind a campaign of several thousand recipients, delivery and read receipts can arrive tens of minutes late. Replies, clicks, unsubscribes and analysed conversations are not delayed.
- “At the end of a conversation”: after 25 minutes without a message, then the analysis pass, every 5 minutes. Expect about half an hour after the last message: enough for a follow-up, not for an immediate alert.
- After an outage of more than 24 hours, depending on the tool, a pending event may not go out. Only the record’s state read at sending time then goes out (its id, unsubscribes, last analysis); never what the event alone told (last reply, RCS reachability), which would overwrite a more recent state.

## The events

Values of `origine` : `humain`, `scenario`, `ia`, `mba`, `campagne`, `mcp`, `api`; of `canal` : `whatsapp`, `rcs`. A missing score (satisfaction, urgency) means “no measure”: it never overwrites the previous one.

| Event | When | Fields |
| --- | --- | --- |
| `em_message_delivered` | Within a minute; delayed behind a large campaign | `canal` `origine` `send_id` : send_id: the send (sendId) the message belongs to, only when it belongs to one |
| `em_message_read` | Within a minute; delayed behind a large campaign | `canal` `origine` `send_id` : Same fields as delivery |
| `em_message_failed` | Within a minute; delayed behind a large campaign | `canal` `origine` `send_id` `motif` `code_meta` : motif: the failure reason, when known. code_meta: Meta’s error code, for a WhatsApp message |
| `em_replied` | Within a minute, even during a large campaign | `canal` `bouton` : bouton: the label of the tapped button. Never the message text. A reaction (emoji) is not a reply. |
| `em_link_clicked` | Within a minute, even during a large campaign | `lien` `template` `destination` : lien: the tracked link code. Only when the click is attributed to a contact; an automatic click (preview, bot) does not count. destination: the address the link leads to, absent beyond 300 characters (a cut address would be wrong). |
| `em_opted_out` | Within a minute, even during a large campaign | `canal` `source` : canal: only when the person wrote STOP on that channel; absent for an unsubscribe set by your team or through the API. source: where the refusal comes from (whatsapp_stop, rcs_stop, crm, api…). |
| `em_conversation_analyzed` | At the end of a conversation | `intent` `sentiment` `satisfaction` `urgence` `resolved` `topic` `action_suggestion` `handled_by` `exchanges_count` `summary_1` `summary_2` `summary_3` : summary_1 to summary_3: the summary, only when the option is on, in chunks of at most 300 characters, to join end to end with no separator (the last ones are absent when it is short). |
| `em_risk_changed` | Every night, when the level changes | `niveau` `ancien_niveau` `score` `raisons` : niveau and ancien_niveau: inconnu, faible, moyen or eleve. raisons: up to three codes separated by commas (silence_60j, silence_30j, sans_reponse, non_lu, reclamation, negatif, insatisfait, injoignable, stop, bloque). |

```
    "message_id": "wamid.…",
    "message_type": "text",
    "text": "Bonjour, où en est ma commande ?",
    "transcription": null,
    "button": null
  }
}
```

- id is stable: the same on retry and replay. Keep processed ids to ignore a duplicate (delivery is “at least once”).
- No ordering is guaranteed between two events: a read message may arrive before the delivered one.
- The content is frozen when the event happens: a retry sends exactly the same body.

<a id="signature"></a>

## Verifying the signature

The format is Standard Webhooks: three headers, `webhook-id`, `webhook-timestamp`, `webhook-signature`, and an HMAC-SHA256 signature of `id.timestamp.corps` with the key after whsec_ in your secret. Standard Webhooks libraries in every language verify it as is.

_Verification in Node.js_

```
import crypto from 'node:crypto';

// Le corps BRUT reçu (une chaîne), jamais l’objet déjà analysé : la signature porte sur ces octets-là.
export function verifier(corpsBrut, entetes, secret = process.env.MESSAGINGME_WEBHOOK_SECRET) {
  const id = entetes['webhook-id'];
  const horodatage = entetes['webhook-timestamp'];
  // Refuser un envoi de plus de 5 minutes : un rejeu d’un message intercepté ne passe pas.
  if (Math.abs(Date.now() / 1000 - Number(horodatage)) > 300) return false;
  const cle = Buffer.from(secret.replace(/^whsec_/, ''), 'base64');
  const attendue = crypto.createHmac('sha256', cle).update(id + '.' + horodatage + '.' + corpsBrut).digest('base64');
  // Plusieurs signatures pendant une rotation du secret, séparées par une espace : une seule suffit.
  return entetes['webhook-signature'].split(' ').some((s) => {
    const [version, valeur] = s.split(',');
    return version === 'v1' && valeur.length === attendue.length
      && crypto.timingSafeEqual(Buffer.from(valeur), Buffer.from(attendue));
  });
}
```

> **Required**
>
> Store the secret in an environment variable of your app, never in the code nor in a file tracked by git. It is shown only once; a lost secret is rotated (the old one keeps signing for 24 h).

<a id="reessais"></a>

## Response and retries

- Answer 2xx within 10 seconds: the event is delivered. Do long work after answering.
- Any other answer, or none, triggers a retry: 30 s, 2 min, 10 min, 30 min, then hourly, for 24 h.
- 410 Gone stops retrying that event. Redirects are not followed.
- Each delivery is visible in the address log (body sent, response, attempts) and can be replayed in one click.

## The events

Each address picks its types. Delivery receipts are unchecked by default: a campaign produces up to three per recipient.

| Type | When | data fields |
| --- | --- | --- |
| `message.received` | A contact writes to you (text, tapped button, media, form reply). | contact, channel, message_id, message_type, text, transcription, button |
| `message.delivered` | Meta confirms one of your messages was delivered. (unchecked by default) | contact, channel, message_id, origin, send_id |
| `message.read` | The contact read one of your messages. (unchecked by default) | contact, channel, message_id, origin, send_id |
| `message.failed` | One of your messages could not be delivered. (unchecked by default) | contact, channel, message_id, origin, send_id, reason, meta_code |
| `link.clicked` | The contact clicked a tracked link. | contact, link, template, destination |
| `contact.opted_out` | The contact opted out (STOP, record, bulk action, API). | contact, channel, source |
| `conversation.analyzed` | A conversation analysis is ready (Enterprise plan). | contact, conversation_id, intent, sentiment, satisfaction, urgency, resolved, topic, action_suggestion, handled_by, exchanges_count, summary |
| `contact.risk_changed` | A contact’s disengagement risk changed level (nightly run). | contact, level, previous_level, score, reasons |
| `template.status_changed` | Meta ruled on one of your templates (approved, rejected, paused, disabled). No contact data. | template, status, reason |
| `agent.action` | An AI agent triggered one of your actions during a conversation (once a day per contact and action): the collected fields are in fields. (unchecked by default) | contact, conversation_id, agent, action, fields, channel |
| `conversation.needs_reply` | “My app answers” mode: a message awaits your app’s answer, at the address set as the responder. | contact, conversation_id, channel, message_id, message_type, text, transcription, reply_with |
| `test` | The “Send a test” button, or the send_test_event MCP tool. | message |

The contact carries its id, number (phone), name, external id and opt-outs.

<a id="repondre"></a>

## My app answers

Pick an address in “Who answers the customer” (Home), or with the set_default_responder MCP tool in application mode: each message nobody handles reaches it as `conversation.needs_reply`, with no type to check, ahead of other deliveries. Your app answers through the API, with the workspace API key:

_POST /v1/messages/whatsapp_

```
{
  "contactId": "8b1e07c4-…",
  "text": "Bonjour Claire, votre commande part demain."
}
```

- Answer the webhook 2xx right away, then send the reply: the conversation stays with your app, out of the team’s “To handle” queue.
- The 24-hour window applies: the reply goes out as long as the customer wrote in the last 24 hours.
- Answer conversation.needs_reply only: if the address also receives message.received, the same message arrives twice, and answering both would reply twice. The API key needs the sends:create scope.
- These replies count toward no API daily quota; the per-minute cap applies.
- No fallback: if your app does not answer, nobody does in its place. A paused or deleted address, or one beyond your plan, hands the messages back to the team.

<a id="debit"></a>

## Rate limit

- A cap on calls per minute and per hour, set by the workspace’s plan.
- Shared by all the workspace’s keys and the MCP server.
- A call counts as one whatever its size (50 records at once: one call).
- Higher limit for a workspace: on request.

Every counted response carries, in headers, the counter closest to its limit:

| Header | Meaning |
| --- | --- |
| `x-ratelimit-limit` | The limit of this window (minute or hour). |
| `x-ratelimit-remaining` | The calls left in this window. |
| `x-ratelimit-reset` | Reset time, in seconds since 1970. |
| `retry-after` | On a 429: seconds until the full window resets (minute or hour, named in the message). |

- On overflow: 429 `rate_limited`. A refused call does not count.
- Unknown key (401): none of these headers.

<a id="quotas"></a>

On top of the rate limit, DAILY quotas per workspace count the work REQUESTED (a recipient skipped later still counts), in three families counted separately:

| Family | What it counts | Daily quota |
| --- | --- | --- |
| Templates | The recipients of a send, and sending a template from the MCP server | Set by the plan |
| Replies | Free-form WhatsApp or RCS messages, within the 24-hour window. Sending templates never takes their room. | Set by the plan |
| Records | Written contacts (one per contact, multi-contact calls included) | 20000 |

- Reset at midnight, Paris time.
- A request that would exceed the quota is refused entirely: 429 `quota_exceeded`, with retry-after until midnight. A smaller request may still go through.
- A new call with the same idempotency key does not count, whether it replays a finished send or hits one in progress (409). A send refused by the quota frees its key.
- Reads, catalogs and campaigns launched from the console have no quota. Neither does the MCP server, except sending a template, which counts as a template.
- Higher quota for a workspace: on request.

> **Note**
>
> Counters kept in the database and shared by every server copy: a deploy does not reset them.

## Errors

Shape of a refusal:

_JSON_

```
{
  "error": "fenêtre de 24 h fermée : cette personne n’a pas écrit récemment. Utilisez un template (POST /v1/sends).",
  "code": "window_closed"
}
```

- error: sentence in French, for a human. code: stable identifier, for a program.
- A refusal carries the same code everywhere, as an error or as a skip reason in a send.
- Readable but malformed JSON body: invalid_body, faulty field in the message. Missing or unreadable record key: invalid_recipient, invalid_phone.

| Status | Meaning |
| --- | --- |
| 400 | Invalid body. |
| 401 | Key missing or invalid. |
| 403 | Scope missing, or workspace suspended. |
| 404 | Record, send or target not found. |
| 409 | The state of the record or workspace forbids the operation: opted out, blocked, no consent, contradictory keys, channel or number missing, ambiguous scenario name, idempotency key in use. |
| 422 | Valid body, but sending is impossible as things stand: window closed, unsendable target, unreadable category, record without a number, number unreachable over RCS, idempotency key already used, Meta refusal. |
| 429 | Rate limit or daily quota exceeded. |

Every code, when it happens and what to do, with Meta’s errors: [the error catalog](https://console.messagingme.app/developers/api/errors.en.md).

> **Caution**
>
> An unreadable JSON is read as an empty object: the refusal names what is missing, not the syntax. Always send Content-Type: application/json.

# Error catalog

Every error response of the API carries a JSON body with error, a French sentence for a human, and code, a stable identifier for a program. Rely on code, never on the sentence.

<a id="forme"></a>

## The shape of an error

_JSON_

```
{
  "error": "fenêtre de 24 h fermée : cette personne n’a pas écrit récemment. Utilisez un template (POST /v1/sends).",
  "code": "window_closed"
}
```

- `metaCode`: on meta_rejected only, Meta’s error number (see below), or null when Meta gives none.
- `upgradeUrl`: on a 402, the page where the workspace plan is changed.
- `retry-after`: on a 429, the header that says how many seconds to wait.

> **Caution**
>
> A 5xx may arrive without this body: a generic error page sometimes replaces it on the way. Treat it as internal_error: retry with a growing delay, and replay a send with the same idempotency key.

What to do: Identify the person with at least one key: contactId, externalId, phone or bsuid.

<a id="meta"></a>

## Meta errors

Meta sometimes refuses a message for a reason of its own. Its error number arrives in four places:

- `metaCode` of a 422 meta_rejected refusal, when Meta refuses on the spot;
- `data.meta_code` of the message.failed event, when the message fails after it went out;
- `error.code` of a message read with GET /v1/messages/{messageId};
- `error.metaCode` of a recipient in a send’s follow-up (GET /v1/sends/{sendId}).

The codes below are the ones that concern a Messaging Me workspace. The full list is in Meta’s Cloud API documentation.

### The recipient

<a id="meta-131047"></a>

#### `131047`

More than 24 hours since the person’s last message: the window is closed.

What to do: Send an approved template (POST /v1/sends) instead of a free-form message.

What Messaging Me already does: When it knows, the API refuses before Meta: window_closed.

<a id="meta-131026"></a>

#### `131026`

Undeliverable message: the number is not on WhatsApp, the person has not accepted WhatsApp’s terms, or their app is too old.

What to do: Use another channel (RCS, email), or ask the person to update WhatsApp.

What Messaging Me already does: A multi-channel campaign moves to the next channel. Otherwise, when retry is on (the campaign box, or the workspace setting for an API send), it retries once, then marks the contact unreachable on WhatsApp.

<a id="meta-131049"></a>

#### `131049`

Marketing message not delivered: Meta limits the marketing each person receives, to preserve engagement.

What to do: Do not retry right away: wait at least 24 hours. Meta does not say when the limit lifts.

What Messaging Me already does: When retry is on (the campaign box, or the workspace setting for an API send), it is tried again the next morning.

<a id="meta-131050"></a>

#### `131050`

The person has opted out, in WhatsApp, of your business’s marketing messages.

What to do: Do not retry, and stop sending them marketing.

<a id="meta-131021"></a>

#### `131021`

The sender and the recipient are the same number.

What to do: Send to a number other than the workspace’s own.

<a id="meta-130497"></a>

#### `130497`

The account cannot message people in this country.

What to do: This recipient cannot be reached by this account: check the allowed countries in Meta’s policy.

### Templates

<a id="meta-132000"></a>

#### `132000`

# MCP server

Connect an assistant (Claude, or any MCP-compatible client) to the workspace, with no integration to build.

## Claude Code: the plugin

The simplest way in Claude Code: the Messaging Me plugin connects this server with no key, then /messagingme:demarrer sets the workspace up step by step (number, AI agent, bubble, test). The two commands, one after the other, then /mcp, plugin:messagingme:messagingme and Authenticate. With the plugin, do not also add the key-based command below: Claude Code would keep that server, which does not open the setup tools.

_Command 1_

```
/plugin marketplace add julienmessagingme/messagingme-plugin
```

_Command 2_

```
/plugin install messagingme@messagingme
```

_Then, in Claude Code_

```
/messagingme:demarrer
```

## Endpoint

_Endpoint_

```
https://api.messagingme.app/mcp
```

_Command to copy_

```
claude mcp add --transport http mba https://api.messagingme.app/mcp --header "Authorization: Bearer VOTRE_CLE"
```

Replace VOTRE_CLE with an API key holding an MCP scope. [Create a key](https://console.messagingme.app/developers/keys)

## Connect another client (ChatGPT, Cursor, VS Code, Lovable)

- Add a remote MCP server (or a connector) at https://api.messagingme.app/mcp, with no key, using OAuth authentication: the client opens our authorization page, where a workspace administrator signs in and picks the workspace.
- The page says where the client’s name comes from: verified for Claude, published by its domain for a client with an identity document (ChatGPT), unverified for a client that registers itself (Cursor, VS Code).
- The client receives its code on an https address, or on localhost and 127.0.0.1: a return through an app scheme (cursor://) is refused.

## What it does not do

- **No campaigns.** It sends a template to one person at a time, signed in as you; it does not launch a mass send.
- **Outside the 24 h window, only an approved template goes out.** A free-form message is refused, with the reason; an approved template goes out through send_template_to_contact.
- **WhatsApp number unlinked, nothing is sent.** The tool refuses, with the reason, until an admin relinks the number from the Home page.
- **Automations are not triggered.** A tag set by the assistant classifies the contact, without waking the automations listening for that tag.
- **Activating an AI agent does not make it answer.** Created and activated by the assistant, it talks to customers inside a published scenario that contains it, or once chosen to answer the customer (set_default_responder, “agent” mode): it then answers every message nobody handles, and Meta’s agent, if on, stays on standby.
- **Access goes through a key or an OAuth connection.** Either one carries the workspace and the scopes. To cut an assistant off: revoke its key or its authorization under "API keys".
